# 03 · 验收标准

**先读 `00-参考来源与项目定位.md`。**

## 这份文档的规矩

**每一条都必须是可判定的。** 不接受"基本能用"、"大致正常"、"体验良好"这种结论。每条要么给出**具体数值**，要么给出**具体操作步骤 + 预期结果**。

**给 AI 的执行要求：**

1. 每做完一个功能，回来把该功能的全部条目走一遍
2. 勾不上的，**要么继续做，要么明确写出做不了的原因** —— 不许跳过去做新功能
3. **不许写假实现**：按钮存在但点了没反应、返回写死的假数据、异常被吞掉只打印日志，都算不通过
4. 标 **🔴 红线** 的条目，任何一条不通过就必须立刻停下来改，不能带着往下走

**核心功能（图片、视频、画布）的标准比其他功能严。** 那三块是这个工作台的立身之本，宁可其他功能晚做，也不许核心功能半残。

## 零、红线（先过这一关）

任何一条不通过，其余验收全部作废。

- 🔴 不选任何 skill，输一句提示词能直接出图 —— ✅ 真机实测：mock 与真实渠道均直接出图
- 🔴 skill 评分再低，「出图」按钮仍可点击（DOM 上没有 disabled）—— ✅ 代码 `$('go').disabled = false`，真机确认
- 🔴 评分低时不弹窗、不要求二次确认、不自动重试 —— ✅ 仅有"有弱项仍可出图"文字提示，无弹窗逻辑
- 🔴 全程不存在"这个我不能生成"类的拒绝 —— ✅ 全库 grep 无拒绝文案与拦截分支
- 🔴 没有敏感词过滤、没有关键词黑名单、没有内容审查 —— ✅ image-guard 已改为直通扩展点（原 CSAM/bomb 两条正则已删除），真机用原黑名单关键词实测放行出图
- 🔴 自动带上的负面词在界面上看得见，且能删掉 —— ✅ 负面词输入框可见可编辑
- 🔴 skill 指定的比例显示在界面上，用户手动改能改动 —— ✅ 比例 chips 可改，generate 以用户选择优先
- 🔴 不自动删除任何已生成的图片或视频 —— ✅ keepLastTasks 默认改为 0（prune 短路），生产代码无任何自动删除调用；回归测试 AC-STORE-7D 锁定
- 🔴 不自动改写用户输入的提示词（用户主动点「增强」除外）—— ✅ 增强为手动按钮，generate 原样透传 prompt
- 🔴 密钥在浏览器开发者工具、日志、报错信息里均不可见 —— ✅ 真机扫描 localStorage+页面 HTML 无 sk- 明文；request.json 经 redactSecrets（测试 AC-SEC-03）；报错仅含环境变量名

## 四、核心功能 2：视频生成

**标准与图片同级。视频不是附属功能。**

- [x] 🔴 **没有插件套插件**：视频协议内置在代码里，用户只需在设置里填地址密钥，不需要 clone 插件包、放目录、重启（视频内置于 provider-openai，设置页一个 videoModel 字段）

- [x] 上游失败时，**原始失败原因透传给用户**（真机：`video API 503: 上游原文` 完整显示）
