# DSH Image Studio 插件 · 设计规范

> 本文是可执行约束。违反不合并。  
> 版本：v0.2，与《01-设计文档》形态修正对齐。

---

## 1. 工程规范

### 1.1 包与模块

- 一包一事。UI、tools、skills、assets、compose、guard、provider 不得混在单文件里「先跑起来」。
- `dsh-image-ui` 是发布必装包，不是示例。
- 包名 `dsh-image-*`；bundle 入口 `plugin.ts` 的 `name` 为 `image-studio`。

### 1.2 插件骨架

每个包导出 `name` / `inject` / `apply`；有配置则导出 Schemastery `Config`（不得导出普通对象冒充）。  
无顶层副作用。注册必须包在 `ctx.effect` 或 `ctx.plugin` 子纤维里，卸载可逆。

### 1.3 依赖

- UI Host 探测 `webServer`，不得把无 web 的测试环境卡在 PENDING（`webServer` 不进必填 inject；有则注册路由）。
- Tools 必填 `tools` + `imagegen` + `imageSkills` + `imageAssets` + `imageCompose`。
- 禁止 UI 直接打第三方生图 HTTP；必须走 `ctx.imagegen`。

## 2. 产品形态规范

### 2.1 入口

- 官方 DSH 侧栏「新会话」旁必须有「生图」。
- 「生图」打开工作台；「对话」/「新会话」回到 agent loop。
- 同源路径 `/imagestudio` 必须可打开同一工作台。
- 「设置 → 插件 → 插件配置」不是入口。空配置页不视为失败；失败是侧栏没有「生图」。

### 2.2 禁止的实现

- 禁止复制 VisioWork / Nova 源码（含 CSS 模块、组件名、文案库）。
- 禁止另开端口冒充 DSH。
- 禁止用精简/手戳预览冒充官方 Harness。
- 本期禁止做无限画布、电商模式。

### 2.3 工作台最低控件

必须能完成：选 skill、写简报、文生图、图生图、策划预览、反推、三联、看本 session 产物。  
cinema-dna 选择后画幅控件锁 21:9，用户不能改成 1:1 再出图。

## 3. Skill 在 UI 中的规范

1. 五个 skill id 必须出现在选择器，id 与磁盘目录名、`preset.yaml` 的 `id` 一致。
2. 点「开始生成」的第一件事是 `compile` + `score`，不是直接 `generate`。
3. `selfCheck.passed === false` 时 UI 必须展示 score 与 failures，且不得调用 provider。
4. movie-poster 的 3:4 只在简报显式包含海报/封面/片名时启用。
5. describe 的文本只出现在反推面板，禁止写入 `systemPrompt`。
6. 三联必须走 `imageCompose.triptych`，禁止把「请画三格」写进 prompt。

---

## 4. 事件规范

与 v0.1 相同：

| 事件 | 模式 | 纪律 |
|---|---|---|
| `image/plan` | serial | 可改 plan |
| `image/score` | serial | 可改 selfCheck |
| `image/guard` | bail | 返回即拦截 |
| `image/before-request` | waterfall | 观察者也必须 `next()` |
| `image/after-result` | parallel | 不得挡主路径 |
| `image/progress` | parallel | UI 可订以画进度 |

工作台 API 与工具必须走同一条事件链。允许 UI 自己打分展示，不允许 UI 绕过 guard。

---

## 5. 工具规范

6 个工具名、参数名、错误码与 v0.1 验收表一致。  
`defineTool` 的 `output.schema` 必须是 JSON Schema object；`render` 只返回官方 ContentBlock。  
工具与工作台对同一 brief+skill 应得到同一 CreativePlan（允许 uuid 不同，shots/constraints/score 判定一致）。

错误分类：`INVALID_ARGS` / `PROVIDER_UNAVAILABLE` / `TIMEOUT` / `CANCELLED` / `GUARD` / `VETO`。

---

## 6. 任务与产物规范

- 排队、取消、超时：`ctx.jobs` 或宿主等价物 + AbortSignal。
- 历史：当前 session；不得把 A session 的图默认列进 B session。
- 落盘：`.dsh/image-studio/<sessionId>/<taskId>/`，路径沙箱。
- `plan.json` / `request.json` 必须脱敏，禁止写 api key。
- 工作台与工具写入同一 store，素材库两边都能看见。

---

## 7. 配置与密钥

- `Config` 用 Schemastery；密钥字段 `.role('secret')`，只存 `apiKeyEnv`。
- 值只出现在 `$DSH_HOME/.credentials.yaml` 或环境。
- settings 卡（若做）读写同一 namespace，不得另存一份 localStorage 真源。

---

## 8. Client / Host 规范

- Host：`/imagestudio`、`/imagestudio/entry.js`、`/imagestudio/api/*` 注册在官方 `ctx.webServer`。
- Client：`package.json` 的 `dsh.client` + `exports["./client"]`；只做壳入口与配置卡。
- tapIndex 注入的脚本必须幂等（重复加载不得出现两个「生图」）。
- 卸载插件后「生图」按钮与 `/imagestudio` 路由必须消失。

---

## 9. 文档规范

- 设计文档不得再写「这不是把 Nova 的网页搬进 dsh」来否定独立工作台。
- 可以说「不搬 Nova 源码」，不能说「没有独立页面」。
- 验收项必须能指向「侧栏生图」或 `/imagestudio`，不能只指向工具 schema。

---

## 10. 版本

v0.2 起独立工作台为稳定形态。删除「生图」入口视为破坏性变更。
