# 02 · 设计规范

**先读 `00-参考来源与项目定位.md`。**

规定"该做成什么样"，不规定"代码怎么写"。

## 标记含义

- **【必须】** 照做，数值原样使用，不要自己调整或"优化"
- **【自定】** 给了方向，具体实现你决定
- 未标记的叙述：背景和理由

## 本文没写到的怎么办

优先级从高到低：

1. 五个 skill 的 `SKILL.md` 原文 —— 创作规则的权威来源
2. dsh-imagegen 的 README —— 交互形态的权威参考
3. 自己判断，但在代码注释里写明做了什么假设

**不要因为本文没写就跳过某个功能**，也不要自己加本文和需求文档里都没提的功能。

## 一、总的原则

### 用户说了算

**【必须】** 这条排第一，因为最容易被"好心"违反。

工作台的职责是**把活干好**，不是**判断用户该不该干**。

不允许出现的东西：

- 内容审查、敏感词过滤、关键词黑名单
- "这个我不能生成"之类的拒绝
- 因为评分不够而禁用出图按钮
- 因为评分不够而弹窗拦截、要求二次确认
- 自动重试、自动改写用户的提示词（增强功能除外，那是用户主动点的）

允许并且应该有的：

- 提示、建议、警告文字 —— 但都是看完可以直接无视的，不挡路

反过来，**什么是该强制的：用户已经选择的东西要兑现。** 选了电影三联就真的出 21:9 三张、真的本地拼接、真的带上负面词。这不是限制用户，这是把用户要的效果做对。区别在于：前者是替用户做决定，后者是执行用户的决定。

### skill 的规则不要搬进代码

- **【必须】** 运行时读本地 skill 目录，不把 skill 内容硬编码
- **【必须】** skill 自带校验脚本的（海报 skill 有），调用它，不要在自己这边把规则重写一遍

理由：重写一遍就会不同步。作者更新了 skill，你的代码还在跑旧规则，而且你不会察觉。

### 每一步都是能用的

不要做一半的功能。宁可少一个页面，不要四个页面都半残。

## 二、页面规范

### 布局

**普通生图页**固定三栏：历史记录 | 生图区 | 对话面板。

- 对话面板默认收起，点顶部按钮展开
- 各栏宽度能拖，拖完记住
- 顶部是页面切换：普通生图 / 画廊 / 无限画布 / 电商模式

**其余页面**自己定布局，但顶部切换栏保持一致，位置不要跳。

### 三个核心功能的地位

**【必须】图片、视频、画布三者平级。**

- 视频不是图片的附属功能，不许做成"图片页面里加个视频开关"
- **【必须】视频协议内置在代码里，不做插件套插件。** 本项目本身就是 dsh 插件，再套一层插件体系没有意义。加新视频模型 = 加一个协议适配，不是让用户去 clone 插件包放目录
- 三者共用同一套：任务队列、历史记录、画廊、存储、渠道配置界面
- 画布上要能同时处理图片和视频节点

### 一致的东西

这些在所有页面里得一样，不然用着别扭：

| 东西 | 规定 |
|---|---|
| 比例选项 | **【必须】** 固定这 9 项且顺序固定：自动、1:1、3:4、4:3、9:16、16:9、2:3、3:2、21:9。所有页面用同一份定义，不要各页各写一份 |
| 清晰度 | **【必须】** 4 档：自动 / 1K / 2K / 4K |
| 张数 | **【必须】** 1、2、3、4 四个档位 |
| 图片能干什么 | 下载、加画廊、加对话、当参考图、重新生成、复制提示词、拿去做视频。凡是显示图的地方，这几个动作都应该有 |
| 视频能干什么 | 播放、下载、加画廊、抽帧、重新生成。抽出来的帧要能当图片用（转参考图 / 加画布） |
| 视频 URL | **【必须】** 上游返回什么就用什么，**不做域名改写、不做代理转发** |
| 加载中 | 显示进度和已用时间，能取消 |
| 出错了 | 说清楚哪儿错了，给个重试按钮。别只弹一个"失败" |

### 空状态

每个页面空着的时候别是白板：

- 生图页：灵感案例卡片，点了填提示词，有「随机」换一批
- 画廊：说明怎么把图加进来
- 画布：自带一组文本 + 配置节点，开箱能用
- 电商：说明要传什么图

### 别打断用户

- 生图跑着的时候，页面照常能操作，能切页面、能改参数准备下一次
- 长任务不要弹模态框挡着
- 需要确认的只有一种：**会花钱且量大的**（比如电商套图批量生成、多模型对比）。这种先显示"要生成 N 张"，确认再跑

## 三、创作 Skill 规范

### 定位

skill 是**帮用户想画面的工具**，摆在生图区作为可选项。不选就是普通生图，跟没这功能一样。

### 流程

```
写一句想法  →  点「想方案」  →  看方案  →  想改就改  →  出图
                                  ↓
                            不满意 → 重新想一版
```

### 方案长什么样

方案摊开给用户看，分两块：

**第一块：它是怎么想的。**

这块是给人看的，**用大白话写**。比如电影三联的方案应该像这样：

> 这场戏的核心是一个没法解决的僵局：证据摆在桌上，但没人敢先开口。
> 观众站在门口，像个刚进来还没来得及坐下的人。
> 视线从桌上的卷宗，扫到主审官的手，最后停在门外那双没进来的鞋上。
> 颜色上：褪了色的朱红，泡在潮湿的青灰里。红不是喜庆，是还没干透的印泥。
> 三个镜头的变化：先远看整个厅堂，再切到桌面细节，最后拉到门缝外的视角。

不要写成"构图压力：高。视线流量：左下→右上。色彩命题：红/青对比。"——那是给机器看的，用户看不出所以然。

**第二块：具体参数。**

每张图的提示词、比例、负面词。这块允许技术一点，因为用户要改它。

### 改方案

方案的每一部分都能改：

- 判断部分改了，提示词要跟着重新生成（或者提示用户"你改了判断，要不要重新生成提示词"）
- 提示词能直接编辑
- 比例、张数能改
- 改完能存成自己的模板，下次直接用

### 自检评分怎么展示

skill 里带打分表的（电影三联 100 分、海报 100 分），跑完显示出来：

- 显示总分和各项得分
- 哪项低就说哪项，用大白话说清楚为什么低
- **给两个按钮：「就这样出图」和「重新想一版」**
- 默认焦点在「就这样出图」上

**不允许的做法：** 分数不够就禁用出图按钮、自动重试、弹窗警告、需要二次确认。分数是参考，不是关卡。

### 参数怎么落实

skill 定的这些要真的生效，因为这是用户选它的原因：

| 项 | 怎么做 |
|---|---|
| 比例 | 按 skill 定的来（三联 21:9、海报 9:16、封面 3:4）。界面上显示当前是这个比例，**用户手动改能改得动** |
| 张数 | 三联就是 3 张 |
| 负面词 | 自动带上，不用用户每次手打。界面上能看到带了什么，也能删 |
| 拼接 | **【必须】** 本地拼接，纵向排列，相邻两张之间纯黑间隔 **8–12 像素**（取 10 即可），**不加**文字、序号、水印、边框、圆角、阴影。三张单图和拼接图都要保存 |
| 参考图 | skill 模式下默认只做分析，不当图生图底图。用户要图生图就切图生图模式 |

### 五个 skill 的入口

界面上得让人一眼知道该点哪个，别让人猜：

| 入口名字 | 对应 | 出什么 |
|---|---|---|
| 电影三联 | cinema-dna | 3 张 21:9 + 拼接长图 |
| 三联封面 | cinema-dna 的封面阶段 | 1 张 3:4（需要先有三联） |
| 电影海报 | fantasy-movie-poster | 1 张 9:16，分层出 |
| 人像 | life-force-portrait | 升级已有照片 / 原创人像，两个子选项 |
| 摄影 | photography-simulation | 摄影感画面 |
| 角色 | character-casting | 一张人物图；勾「三视图」才出多角度 |

「三联封面」和「电影海报」是两个不同的东西，名字上就要区分开，别都叫"海报"。

### 海报的分层

海报按原作者的路子分层做：

1. **底图层** — 只有画面没有字
2. **字体层** — 只有字没有画面，纯黑底白字或纯白底黑字
3. **合成图** — 两层叠在一起
4. **一份记录** — 记下画布尺寸、各层位置缩放叠加方式，以后能复现

字体层由图像模型出，本地只做裁剪、缩放、挪位置、叠加、调透明度。**本地不打字。**

字可能会错。界面上给一个「只重出字体层」的按钮，底图不动，重试成本低。**不自动检测不自动重试**，用户自己看着办。

### skill 从哪读

- 读本地一个目录，路径可配
- 目录里有哪些 skill 就显示哪些，没装的不显示
- 界面上给一句话说明怎么装（clone 到那个目录）
- 标注作者出处

## 四、出图规范

### 渠道配置

- 一个渠道 = 地址 + 密钥 + 一批模型
- 能配多个渠道同时用
- 保存后能「检测可用模型」，把聊天模型、向量模型过滤掉
- 检测不出来的能手动加
- 能给模型起别名（模型 ID 太长了）
- 能设默认：文生图用哪个、图生图用哪个、提示词增强用哪个

### 协议适配

不同家接口差别挺大，都得能接：

- 标准 OpenAI 图片接口
- 异步两步式的（提交拿 ID，轮询取结果）——自动轮询，别让用户等在那不知道发生什么
- 豆包 Seedream、通义 Qwen-Image、MiniMax、Grok Imagine、Gemini 系列这些各自的协议

**要求：换渠道对用户是透明的。** 选哪个模型，界面操作都一样，协议差异藏在里面。

### 任务

- 排队跑，不卡界面
- 显示进度和耗时
- 能取消。取消要真的停掉，不是只是界面不显示了
- 失败能重试，重试不用重新填参数
- 关页面再开，没跑完的任务还在

### 存图

- 存本地，默认在用户目录下，能改路径
- 改了路径之后，新图存新地方，老图不动不删
- 历史、画廊、画布分开存
- 画廊按图片内容去重
- **不自动删图。** 可以提供手动清理，但别自动过期

---

## 五、密钥

只有一条：

**密钥由宿主进程保管，前端只知道配了没配，日志里不出现。** 调上游 API 也是宿主去调，浏览器不直连（顺带解决跨域问题）。

这是防止自己的密钥泄漏，不是功能限制。

---

## 六、性能

自己本地用，要求不高，但别难受：

- **【必须】** 页面打开不超过 2 秒
- 切换标签页要即时，别转圈
- 画廊图多了要能滚得动（虚拟滚动或者分页）
- 画布节点多了别卡：**【必须】** 100 个节点以内操作顺滑
- 生图本身慢是上游的事，但**界面不能跟着卡**

---

## 七、文档要求

自己用也得写，半年后就忘了：

- 怎么装
- 怎么配渠道（每种渠道地址填什么，举例）
- 五个 skill 怎么装、分别干什么、什么时候用哪个
- 图存在哪
- 常见问题：模型检测不出来怎么办、生图一直转圈怎么办、中文字出错怎么办

skill 部分要注明作者出处。
